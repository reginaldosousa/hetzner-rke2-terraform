# 0002. RKE2 como distribuição Kubernetes

- **Status:** Aceito
- **Commits:** `d3ef7f5`, `c314ffb`

## Contexto

Sem Kubernetes gerenciado na Hetzner, precisamos de uma distribuição que suba via cloud-init, tenha etcd HA,
seja segura por padrão e permita que workers efêmeros (Karpenter) entrem sozinhos.

## Decisão

Usamos o RKE2: três servers com etcd embutido (`master-1` inicializa, os outros entram via `:9345`) e workers
como `rke2-agent`. A versão é fixada em `rke2_version` e precisa ser a mesma em masters e workers.

Configuração relevante:

- `cloud-provider-name: external` + `disable-cloud-controller: true`, para que o hcloud CCM defina o `providerID`.
- `node-taint: CriticalAddonsOnly=true:NoExecute` nos masters, deixando cargas comuns para os workers.
- `token` (só masters) e `agent-token` (workers) separados ([0008](0008-secrets-out-of-user-data.md)).

## Alternativas consideradas

- **k3s:** mais leve, mas com perfil de segurança menos rígido e datastore padrão SQLite. O RKE2 é a variante
  "hardened" da mesma família.
- **kubeadm:** exige montar etcd, CNI, ingress e certificados à mão, com mais peças para manter.
- **Talos:** excelente para imutabilidade, mas usa API própria em vez de cloud-init/SSH, e a integração com o
  provider Karpenter da Hetzner (que entrega userData cloud-init) seria mais complexa.

## Consequências

- Instalação em uma linha (`curl https://get.rke2.io | sh`) com versão fixada.
- Canal, CoreDNS, Traefik e metrics-server vêm embutidos. O Traefik é reaproveitado no ingress
  ([0011](0011-ingress-traefik-hetzner-lb.md)).
- Os auto-deploy manifests instalam CCM e CSI ([0016](0016-ccm-csi-auto-deploy.md)).
- Os masters ignoram mudanças de `user_data`, então upgrades do RKE2 nos masters são feitos in-place, não pelo
  Terraform.
- Esquecer `disable-cloud-controller` grava um `providerID` `rke2://` imutável e quebra o Karpenter (aconteceu
  e foi corrigido em `c314ffb`).

## Atualizações
- **2026-10-27:** O instalador não é mais `curl https://get.rke2.io | sh`: os nós baixam o `install.sh` da tag de
  `rke2_version` e só o executam se o sha256 bater com `rke2_install_sha256` (`git log -S rke2_install_sha256`).
